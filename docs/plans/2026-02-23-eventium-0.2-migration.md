# Migrate Backend to Eventium 0.2.0 API — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Migrate the accounting backend from eventium 0.1.x to 0.2.0, updating all APIs, adding domain error types, removing negative events (AccountDebitRejected), rewriting the TransferManager to the pure-react pattern, and converting the event bus to EventPublisher/EventHandler.

**Architecture:** Bottom-up migration: dependency config first, then domain layer (remove AccountDebitRejected, add error types, TypeEmbedding), then infrastructure wiring (EventPublisher, Codec), then tests. Each task should compile (possibly with warnings) before the next.

**Tech Stack:** Haskell, GHC 9.6.7, Cabal, eventium 0.2.0 (local), PostgreSQL, RIO, Servant

**Key design decision — removing AccountDebitRejected:**
The old API used negative events (`AccountDebitRejected`) as saga signals because command handlers returned `[event]` (empty list = silent rejection). The new API has `Either err [event]` — insufficient funds becomes `Left InsufficientFunds` instead of `Right [AccountDebitRejectedEvent ...]`. The TransferManager saga no longer reacts to a rejection event. Instead, the command dispatcher in Infrastructure.Eventium detects `Left` from the debit command and issues `FailTransfer` directly. This makes the PM simpler (no reaction to rejection events) and removes the coupling between account events and the saga.

### Task 0a: Fix `embeddedCommandHandler` — return `Right []` instead of throwing on non-matching commands

**Files:**
- Modify: `eventium/eventium-core/src/Eventium/CommandHandler.hs`
- Modify: `eventium/eventium-core/test/` (add/update test for non-matching command behavior)

**Problem:** `embeddedCommandHandler` (line 110) throws `DecodeError` when the command doesn't match the embedding. This makes multi-aggregate command dispatching impossible — you can't safely try Account, Transaction, and User handlers in sequence because a non-matching command throws instead of returning `Right []`.

The bank example works around this by having only one aggregate. Our backend has three.

**Fix:**

In `embeddedCommandHandler`, change:
```haskell
    embeddedHandler state adaptedCmd =
      case extract commandEmb adaptedCmd of
        Nothing -> throw $ DecodeError "embeddedCommandHandler" "Command type does not match embedding"
        Just cmd -> fmap (map (embed eventEmb)) (commandHandler state cmd)
```
to:
```haskell
    embeddedHandler state adaptedCmd =
      case extract commandEmb adaptedCmd of
        Nothing -> Right []  -- Non-matching command, silently skip
        Just cmd -> fmap (map (embed eventEmb)) (commandHandler state cmd)
```

**Rationale:** This mirrors how `embeddedProjection` works — non-matching events are silently skipped. Commands should behave the same way. A non-matching command is not a programming error in a multi-aggregate system; it's normal routing.

**Impact on backend plan:** With this fix, the `commandDispatcher` in Task 7 simplifies dramatically — we can try all three handlers without manual command inspection:

```haskell
commandDispatcher writer reader uuid cmd = do
  r1 <- applyCommandHandler writer reader accountAccountingCommandHandler uuid cmd
  case r1 of
    Right (_:_) -> pure ()
    _ -> do
      r2 <- applyCommandHandler writer reader transactionAccountingCommandHandler uuid cmd
      case r2 of
        Right (_:_) -> pure ()
        _ -> void $ applyCommandHandler writer reader userAccountingCommandHandler uuid cmd
```

**Commit:**
```bash

git commit -m "fix: embeddedCommandHandler returns Right [] for non-matching commands"
```

```haskell
-- | Create an 'EventHandler' that wires a 'ProcessManager' to a global
-- event store reader and a command dispatcher.
--
-- For each incoming event:
--   1. Rebuilds the process manager state from the global event stream
--   2. Calls 'processManagerReact' with the current state and the new event
--   3. Executes the resulting effects via the dispatcher
processManagerEventHandler ::
  (Monad m) =>
  ProcessManager state event command ->
  GlobalEventStoreReader m event ->
  (UUID -> command -> m ()) ->
  EventHandler m (VersionedStreamEvent event)
processManagerEventHandler pm globalReader dispatch = EventHandler $ \event -> do
  let globalProjection = globalStreamProjection (processManagerProjection pm)
  StreamProjection {..} <- getLatestStreamProjection globalReader globalProjection
  let effects = processManagerReact pm streamProjectionState event
  runProcessManagerEffects dispatch effects
```

```haskell
reactToTransferEvent :: TransferManager -> VersionedStreamEvent AccountingEvent -> [ProcessManagerEffect AccountingCommand]
reactToTransferEvent manager (StreamEvent txUuid _ _ (TransferInitiatedEvent TransferInitiated {..})) =
  case mkTransactionIdSafe txUuid of
    Nothing -> []
    Just txId ->
      case manager ^. transferManagerTransfers . at txId of
        Nothing -> [] -- Idempotency: already processed or invalid
        Just _ ->
          [ IssueCommand
              (unAccountId transferInitiatedFromAccountId)
              ( embed accountCommandEmbedding
                  ( DebitAccountAccountCommand

                          debitAccountTransactionId = txId,
                          debitAccountReason = transferInitiatedReason
```

**Step 8: Add commandDispatcher with debit-failure compensation**

Thanks to Task 0a (`embeddedCommandHandler` returns `Right []` for non-matching commands), we can safely try all three handlers in sequence. The special case is `DebitAccount` — on failure, we issue `FailTransfer` as compensation:

```haskell
commandDispatcher ::
  (MonadIO m) =>
  AccountingVersionedEventStoreWriter m ->
  AccountingVersionedEventStoreReader m ->
  UUID ->
  AccountingCommand ->
  m ()
commandDispatcher writer reader uuid cmd =
  case extractDebitInfo cmd of
    Just (txId, reason) -> do
      -- DebitAccount: handle failure by issuing FailTransfer
      result <- applyCommandHandler writer reader accountAccountingCommandHandler uuid cmd
      case result of
        Left _ -> do
          -- Debit rejected — issue FailTransfer to transaction aggregate
          _ <- applyCommandHandler writer reader transactionAccountingCommandHandler
                 (unTransactionId txId)
                 (embed transactionCommandEmbedding
                   (FailTransferTransactionCommand FailTransfer { failTransferReason = reason }))
          pure ()
        Right _ -> pure ()
    Nothing -> do
      -- Non-debit commands: try each handler in sequence
      -- embeddedCommandHandler returns Right [] for non-matching commands (Task 0a)
      r1 <- applyCommandHandler writer reader accountAccountingCommandHandler uuid cmd
      case r1 of
        Right (_:_) -> pure ()
        _ -> do
          r2 <- applyCommandHandler writer reader transactionAccountingCommandHandler uuid cmd
          case r2 of
            Right (_:_) -> pure ()
            _ -> void $ applyCommandHandler writer reader userAccountingCommandHandler uuid cmd
```
