# Deployment Infrastructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Set up declarative deployment infrastructure — Dockerfile, CI image build, Terraform provisioning, Docker Compose production stack, and manual deploy via `just deploy <env>`.

**Architecture:** Multi-stage Docker image built by GitHub Actions on master push, pushed to GHCR. Hetzner VPS provisioned by Terraform, running Docker Compose (Caddy + app + Postgres). Manual deploy via justfile recipes that SSH into the server.

**Tech Stack:** Docker, Terraform (Hetzner provider), GitHub Actions, Caddy, Docker Compose, Bash.

**Spec:** `docs/specs/2026-03-27-deployment-infrastructure-design.md`

### Task 2: Create multi-stage Dockerfile

**Files:**
- Create: `infra/docker/Dockerfile`

The Docker build context is the repo root (not `infra/docker/`), so paths in the Dockerfile are relative to the repo root. The `.dockerignore` lives at the repo root (where Docker expects it).

**Note:** `accounting.cabal` is committed to the repo (generated by hpack), so the Dockerfile can COPY it directly. The CI `build-image` job still runs hpack to ensure it's up to date.

**Note:** The codebase has an inconsistency: `app/Main.hs` reads `CONFIG_FILE` but the justfile and CLAUDE.md refer to `CONFIG_PATH`. The Dockerfile must use `CONFIG_FILE` to match the actual runtime code. Unifying the env var name is a separate follow-up.

- [ ] **Step 1: Write the Dockerfile**

```dockerfile
# Stage 1: Build
FROM haskell:9.10.3-slim AS builder

RUN apt-get update && \
    apt-get install -y --no-install-recommends \
      libpq-dev \
      zlib1g-dev \
      pkg-config \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /build

# Step 1: Copy dependency files only (cached unless deps change)
COPY package.yaml cabal.project accounting.cabal ./

RUN cabal update && \
    cabal build --only-dependencies -j

# Step 2: Copy source and build
COPY app/ app/
COPY src/ src/
COPY config/ config/

RUN cabal build -j && \
    cp "$(cabal list-bin accounting)" /build/accounting-bin

# Stage 2: Runtime
FROM debian:bookworm-slim

RUN apt-get update && \
    apt-get install -y --no-install-recommends \
      libpq5 \
      libgmp10 \
      zlib1g \
      ca-certificates \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

COPY --from=builder /build/accounting-bin ./accounting
COPY --from=builder /build/config/ ./config/

ENV CONFIG_FILE=config/prod.yaml

EXPOSE 8080

CMD ["./accounting"]
```

Key points:
- `cabal.project.local` is excluded by `.dockerignore` — prevents local eventium path overrides
- Dependencies are installed before source copy — layer caching means deps only rebuild when `package.yaml`/`cabal.project`/`.cabal` change
- All three config files are baked in, `CONFIG_FILE` env var selects which one (`app/Main.hs` reads `CONFIG_FILE`)
- Runtime image has only the binary + configs + minimal runtime libs

- [ ] **Step 2: Verify Dockerfile builds locally (optional, requires Docker)**

```bash

```

Expected: Successful build. May take 10-20 minutes on first run (Cabal dependency download).

## Chunk 2: CI Pipeline Extension

### Task 3: Add build-image job to GitHub Actions

**Files:**
- Modify: `.github/workflows/ci.yml`

- [ ] **Step 1: Read current ci.yml to confirm job name and structure**

The existing job is `build-and-test`. Add a new `build-image` job after it.

- [ ] **Step 2: Add build-image job**

Add the following job to the `jobs:` section of `.github/workflows/ci.yml`:

```yaml
  build-image:
    name: Build & Push Docker Image
    needs: build-and-test
    if: github.ref == 'refs/heads/master' && github.event_name == 'push'
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v4

      - name: Generate .cabal from package.yaml
        run: |
          curl -sSL https://github.com/sol/hpack/releases/download/0.37.0/hpack_linux_amd64.tar.gz | tar xz
          ./hpack

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Extract short SHA
        id: sha
        run: echo "short=$(git rev-parse --short HEAD)" >> "$GITHUB_OUTPUT"

      - name: Build and push
        uses: docker/build-push-action@v6
        with:
          context: .
          file: infra/docker/Dockerfile
          push: true
          tags: |
            ghcr.io/${{ github.repository_owner }}/accounting:${{ steps.sha.outputs.short }}
            ghcr.io/${{ github.repository_owner }}/accounting:latest
          cache-from: type=gha
          cache-to: type=gha,mode=max
```

Key points:
- `needs: build-and-test` — only runs after tests pass
- `if: github.ref == 'refs/heads/master'` — only on master pushes
- `permissions.packages: write` — required for GHCR push
- Hpack runs to generate `.cabal` from `package.yaml` (needed for the Docker build)
- Uses GitHub Actions cache (`type=gha`) for Docker BuildKit layer caching
- Tags with both short SHA and `latest`

### Task 5: Create production Docker Compose

**Files:**
- Create: `infra/docker/docker-compose.prod.yaml`

- [ ] **Step 1: Write docker-compose.prod.yaml**

```yaml
services:
  caddy:
    image: caddy:2-alpine
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
      - "443:443/udp" # HTTP/3
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    environment:
      - DOMAIN=${DOMAIN}
    depends_on:
      accounting:
        condition: service_started

  accounting:
    image: ghcr.io/${GHCR_OWNER}/accounting:${IMAGE_TAG:-latest}
    restart: unless-stopped
    environment:
      - CONFIG_FILE=config/prod.yaml
      - DB_HOST=postgres
      - DB_PORT=5432
      - DB_USER=${DB_USER}
      - DB_PASSWORD=${DB_PASSWORD}
      - DB_NAME=${DB_NAME}
      - JWT_SECRET=${JWT_SECRET}
      - GOOGLE_CLIENT_ID=${GOOGLE_CLIENT_ID:-}
      - GOOGLE_CLIENT_SECRET=${GOOGLE_CLIENT_SECRET:-}
      - GOOGLE_REDIRECT_URI=${GOOGLE_REDIRECT_URI:-}
      - GITHUB_CLIENT_ID=${GITHUB_CLIENT_ID:-}
      - GITHUB_CLIENT_SECRET=${GITHUB_CLIENT_SECRET:-}
      - GITHUB_REDIRECT_URI=${GITHUB_REDIRECT_URI:-}
      - MICROSOFT_CLIENT_ID=${MICROSOFT_CLIENT_ID:-}
      - MICROSOFT_CLIENT_SECRET=${MICROSOFT_CLIENT_SECRET:-}
      - MICROSOFT_REDIRECT_URI=${MICROSOFT_REDIRECT_URI:-}
      - TELEGRAM_BOT_TOKEN=${TELEGRAM_BOT_TOKEN:-}
      - TELEGRAM_BOT_USERNAME=${TELEGRAM_BOT_USERNAME:-}
      - TELEGRAM_WEBHOOK_URL=${TELEGRAM_WEBHOOK_URL:-}
      - TELEGRAM_POLLING_TIMEOUT=${TELEGRAM_POLLING_TIMEOUT:-30}
      - EXCHANGE_RATE_PROVIDER=${EXCHANGE_RATE_PROVIDER:-nbu}
    depends_on:
      postgres:
        condition: service_healthy

  postgres:
    image: postgres:15
    restart: unless-stopped
    environment:
      - POSTGRES_USER=${DB_USER}
      - POSTGRES_PASSWORD=${DB_PASSWORD}
      - POSTGRES_DB=${DB_NAME}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USER}"]
      interval: 5s
      timeout: 5s
      retries: 10

volumes:
  postgres_data:
  caddy_data:
  caddy_config:
```

Key points:
- `GHCR_OWNER` and `IMAGE_TAG` control which image to pull
- `IMAGE_TAG` defaults to `latest` — rollback overrides this with a specific SHA
- All secrets come from the server's `.env` file (Docker Compose reads `.env` automatically)
- Postgres health check gates accounting startup
- Caddy data volume persists Let's Encrypt certificates across restarts

## Chunk 5: Server Bootstrap Script

### Task 7: Create setup-server.sh

**Files:**
- Create: `infra/scripts/setup-server.sh`

- [ ] **Step 1: Write setup-server.sh**

```bash
#!/usr/bin/env bash
set -euo pipefail

# One-time server bootstrap for accounting deployment.
# Run via: just infra-setup
# Prerequisites: Terraform applied, SSH access to server.

echo "=== Installing Docker ==="
apt-get update
apt-get install -y ca-certificates curl
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  > /etc/apt/sources.list.d/docker.list

apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

echo "=== Creating app directory ==="
mkdir -p /opt/accounting

echo "=== Docker installed successfully ==="
echo ""
echo "Next steps (manual):"
echo "  1. Copy docker-compose.prod.yaml and Caddyfile to server:"
echo "     just deploy-sync <env>"
echo "  2. Create /opt/accounting/.env with production secrets"
echo "  3. Log into GHCR: docker login ghcr.io"
echo "  4. Run: just deploy <env>"
```

- [ ] **Step 2: Add deploy recipes**

Append to the justfile:

```just
# --- Deployment ---

# Load deploy env and SSH into server to pull & restart
deploy env:
    #!/usr/bin/env bash
    set -euo pipefail
    source ".deploy.{{env}}.env"
    ssh -i "$DEPLOY_SSH_KEY" "$DEPLOY_USER@$DEPLOY_HOST" \
      "cd /opt/accounting && docker compose pull && docker compose up -d && docker image prune -f"

# Sync docker-compose and Caddyfile to the server
deploy-sync env:
    #!/usr/bin/env bash
    set -euo pipefail
    source ".deploy.{{env}}.env"
    scp -i "$DEPLOY_SSH_KEY" infra/docker/docker-compose.prod.yaml "$DEPLOY_USER@$DEPLOY_HOST:/opt/accounting/docker-compose.yaml"
    scp -i "$DEPLOY_SSH_KEY" infra/caddy/Caddyfile "$DEPLOY_USER@$DEPLOY_HOST:/opt/accounting/Caddyfile"

# Show service status on the server
deploy-status env:
    #!/usr/bin/env bash
    set -euo pipefail
    source ".deploy.{{env}}.env"
    ssh -i "$DEPLOY_SSH_KEY" "$DEPLOY_USER@$DEPLOY_HOST" \
      "cd /opt/accounting && docker compose ps"

# Tail logs from the server
deploy-logs env:
    #!/usr/bin/env bash
    set -euo pipefail
    source ".deploy.{{env}}.env"
    ssh -i "$DEPLOY_SSH_KEY" "$DEPLOY_USER@$DEPLOY_HOST" \
      "cd /opt/accounting && docker compose logs -f"

# Rollback to a specific image SHA
deploy-rollback env sha:
    #!/usr/bin/env bash
    set -euo pipefail
    source ".deploy.{{env}}.env"
    ssh -i "$DEPLOY_SSH_KEY" "$DEPLOY_USER@$DEPLOY_HOST" \
      "cd /opt/accounting && sed -i 's/IMAGE_TAG=.*/IMAGE_TAG={{sha}}/' .env && docker compose pull && docker compose up -d"

# Run setup script on a fresh server
infra-setup env:
    #!/usr/bin/env bash
    set -euo pipefail
    source ".deploy.{{env}}.env"
    scp -i "$DEPLOY_SSH_KEY" infra/scripts/setup-server.sh "$DEPLOY_USER@$DEPLOY_HOST:/tmp/setup-server.sh"
    ssh -i "$DEPLOY_SSH_KEY" "$DEPLOY_USER@$DEPLOY_HOST" "bash /tmp/setup-server.sh"
```
